# Stream Search Dashboard - Handover Document

## Project Overview

A searchable reference page for all live casino stream tables. Given an Excel spreadsheet with table metadata (names, client IDs, locations, stream URLs), this project generates a fast, fuzzy-searchable HTML dashboard where you can find the link to any table without viewing all streams at once.

## Current State (v2.4)

### What Works

- **3 tabs / 112 streams** parsed from `Full Table List (Updated 05.11.26).xlsx` into `data/streams.json` (Religa 57, Eeze 38, Red Panda 17)
- **Live status column** (Religa tab) — each stream’s real state (LIVE / OFFLINE / NO LINK) fetched from the nanoStream bintu API in the browser, with a ⟳ Refresh button and a pulsing-dot live badge. See “Live Status” below.
- **Search dashboard** (`search-dashboard.html`) — compact single-row-per-stream table, all fields visible without horizontal scrolling
- **Fuzzy search** — supports substring, subsequence, multi-word, typo-tolerant (Levenshtein), and ID lookup
- **Category filter** — dropdown auto-populated from data
- **Column filters** — per-tab dropdown row (Status, Partner, Location, Country, Local/Remote on Religa; Partner/Location/Local-Remote on Eeze & Red Panda). All default to "All"; combine with search + category; the Clear button resets them to the default view.
- **Column sort** — click any header to sort (click again to flip direction). Numeric-aware for ID columns; status sorts live → offline → no-link; nulls sort last.
- **Column visibility** — a “Columns” button opens a per-tab show/hide menu; choices persist in `localStorage` and apply to export too.
- **Preset pages** — `game-shows.html` (Game Show tables) and `ezugi.html` (Ezugi tables), each a grid of embedded video cards with live status, linked from the dashboard topbar. Generated by `build_presets.py`.
- **Export filtered results** — CSV / JSON buttons download the currently filtered + sorted view (respects active tab, search term, and category filter). CSV has a BOM for clean Excel opening; filenames are `{sheet}-{YYYY-MM-DD}.{ext}`.
- **Real URLs** — extracted from Excel hyperlink targets (not display text). The "Open" buttons always point to the full playout page; where the source link is a nanoplayer embed, a `playout_url` is derived so the embedded player is never opened in a new tab.
- **Client IDs** — Religa, Ezugi, Vivo, Lucky Streak, ALG (sparse by design: each table is only streamed to a subset of clients)
- **Switcher flag** — Yes/No (41 Yes, 16 No)
- **Dark mode** — fully styled in both themes
- **Polished controls** — pill-style tabs, ghost buttons with hover/press states, and the topbar preset links. (Fixed a legacy `nav a` rule in `style.css` that was painting every `<nav>` link solid blue, which made the Game Shows / Ezugi links invisible — text and background were the same colour.)
- **Auto-refresh** — live status re-checks itself every 90s (skips hidden tabs), so the LIVE/OFFLINE badges and the Hide-offline filter stay current without manual clicks.
- **Keyboard navigation** — ↑/↓ move through results, Enter opens the selected stream, F favorites it. The selected row is highlighted and auto-scrolled into view.
- **Favorites & recent searches** — click the ☆ next to any table (or press F) to favorite it; a **★ Favorites** button filters to just your favorites. Recent searches appear as clickable chips under the tabs. Both persist in `localStorage` (`nano-favorites`, `nano-recent-searches`).
- **Static topbar nav** — the Search / Game Shows / Ezugi pills sit in the same place on every page (CSS grid `1fr auto 1fr` + fixed-width pills + `scrollbar-gutter: stable`), so clicking a pill doesn't make the nav jump.
- **Local server** — `start-dashboard.bat` launches Python HTTP server on port 8080

## How to Regenerate JSON from Excel

**Quick refresh (recommended):** when the Excel changes, just run

```
python refresh.py
```

It re-parses the workbook into `data/streams.json` **and** rebuilds `game-shows.html` / `ezugi.html`, then prints the counts. It warns if the workbook is still open (lock file present). Hard-refresh the dashboard afterwards (`Ctrl+Shift+R`).

To run the steps individually (requires `openpyxl`):

```
cd "D:\LLM Projects\nano"
python parse_excel.py                 # uses the 05.11.26 workbook by default
python parse_excel.py other.xlsx      # or point at a different workbook
```

`parse_excel.py` rewrites `data/streams.json` and prints the per-sheet counts. It applies these cleaning fixes on top of the raw parse:
- strips whitespace from every value (e.g. `" Merit King"`, `"Branded  Roulette"`)
- corrects a few name typos / all-caps via `NAME_MAP` (`MAHNJONG`→`Mahjong`, `Fortune DROP`→`Fortune Drop`, `Dice VIP Roullete`→`Roulette`, `VIVO`→`Vivo`)
- normalises category names (`Live DragonTiger`/`LiveRoulette`/`Roulette` → `Dragon Tiger`/`Live Roulette`)
- normalises partner names to title case (`EEZE`→`Eeze`, `EZUGI`→`Ezugi`; keeps `S.A`)
- blanks out placeholder Religa locations (`-4` / `-3` / `-2`)
- fixes the Eeze `StudioSic Bo` missing-space typo
- maps switcher `True`→`Yes`, `N/A`→`No`
- strips junk query params from stream URLs (expired `jwtoken`, `vtrans*`, analytics) but **keeps `group.id`** (required by the nanoplayer embed URLs)

Raw-parse notes (why the parser does what it does):
- Use `data_only=True` to get computed values (switcher column has `=TRUE()` formulas)
- URLs are in `cell.hyperlink.target`, NOT in `cell.value` (which is just display text) — Religa sheet only
- Religa row 37 ("2xWin") has **no URL** and is **hidden** in Excel (the row is collapsed). It IS included in the JSON (Religa = 57) and shows as NO LINK in the dashboard.
- Religa column 7 (Lucky Streak) can hold a whitespace-only value (stripped)
- Eeze & Red Panda sheets have a DIFFERENT layout: Game Type (col 2), Table Id (col 3), Partner (col 4), Location (col 5), Local/Remote (col 6) — no client IDs, no URLs
- The output JSON is keyed by sheet name under a top-level "sheets" object

## Live Status (Religa tab)

The Religa tab has a **Status** column that shows each stream's real state, fetched live in the browser from the public nanoStream bintu metadata API:

```
https://bintu.nanostream.cloud/stream/<stream-id>
```

- The stream ID is extracted from the playout URL: either `group.id=<uuid>` (nanoplayer embeds) or `/playout/<uuid>`.
- The API returns a `state` field: `live` → **LIVE** (pulsing green dot), `ended` → **OFFLINE**, no stream ID → **NO LINK**.
- The API sends `Access-Control-Allow-Origin: *`, so the page can call it directly — **no proxy or local snapshot needed**.
- A **⟳ Refresh status** button clears the in-memory cache and re-checks all streams. A `statusCache` keyed by stream ID means switching tabs back to Religa does not re-fetch.
- CSV/JSON export includes the readable status label.

> "OFFLINE" is a *current* state, not a broken link — those streams come back when the table goes on air.

### Checking links from the command line

- `python check_links.py` — HTTP 200 check of every URL (8 threads, uses `certifi` for SSL). Writes `data/link-check-<date>.json`.
- `python check_streams.py` — same bintu `state` check the dashboard uses. Writes `data/stream-check-<date>.json`.

> **SSL gotcha:** Python's default CA path on this machine points to a non-existent file, so any site with a normal cert chain (e.g. `bintu-cloud-frontend.nanocosmos.de`) fails verification out of the box. Both check scripts use the `certifi` bundle to work around this.

## Preset Pages (game-shows.html, ezugi.html)

Two dedicated pages show a specific group of tables as a **grid of embedded video cards** (16:9 iframes) with a live status badge on each:

- `game-shows.html` — all Religa tables where `category == "Game Show"` (7 streams)
- `ezugi.html` — all Religa tables where `partner == "Ezugi"` (7 streams)

All three pages (Search, Game Shows, Ezugi) share a topbar **nav** with the current page highlighted (`.preset-link.active`), so you can jump between them from anywhere. Each card shows LIVE/OFFLINE/NO LINK via the same bintu API and has an "Open ↗" link (which points to the **playout** page, not the embedded player — see `playout_url` below). The toolbar has a **▪ Hide offline** toggle (**on by default**) that hides cards that are not currently streaming — "checking" cards stay visible until their status resolves, and the count badge shows e.g. "4 of 7" while filtering. The card grid is a centered flexbox (`flex-wrap: wrap; justify-content: center`, cards `flex: 0 1 380px`) so cards fill the width and any partial last row is **centered** rather than leaving blank space on the right (which matters once the Hide-offline toggle removes cards). A **⟳ Refresh status** button re-checks all streams, and status also **auto-refreshes every 90s** (skips hidden tabs).

The **dark-mode toggle** is a single emoji that shows the theme you'd switch *to* (🌙 in light mode, ☀️ in dark) — `js/dark-mode.js` sets it on load, so it's never the old "Toggle Dark Mode" text. The theme is also applied by a tiny **inline `<head>` script** (before first paint) so there's no light→dark flash on load. The topbar is a 3-section grid (`1fr auto 1fr`): title left, nav centered, toggle pinned to the right edge — so the dark-mode button never touches the nav pills.

**Clean video (no dashboard chrome):** the raw `/playout/<uuid>` URLs load the *full* nanoStream dashboard (header/nav) inside the iframe, so the video looks like "a site in a box". `build_presets.py` therefore rewrites each playout URL to the **nanoplayer embed** URL for the `<iframe>` — that renders just the player. The embed URL is:

```
demo.nanocosmos.de/nanoplayer/embed/2.0.0/nanoplayer.html?group.id=<uuid>&autoplay=true&muted=true&style.displayMutedAutoplay=false
```

- `autoplay=true` + `muted=true` — browsers block autoplay unless muted; this also fixes streams that wouldn't start.
- `style.displayMutedAutoplay=false` — hides the player's centered "tap to unmute" overlay (the `#middleView-playerDiv` element) **while the stream stays muted** (`playback.automute` is left at its default `true`). This is the only lever available because the iframe is cross-origin (no CSS injection), so the param must go in the URL.

The original playout URL is kept for the "Open ↗" link. (The nanoplayer renders to a `<canvas>` via H5Live, not a `<video>` element.)

- Generated by `python build_presets.py` from `data/streams.json` — **re-run it after re-parsing the Excel** to keep the two pages in sync.
- Shared logic lives in `js/preset.js`; the stream list is inlined into each page as `window.__PRESET_STREAMS__`.
- To add a new preset, add an entry to the `PRESETS` list in `build_presets.py` (filename, title, subtitle, predicate) and re-run.

## Known Limitations / Gotchas

1. **Browser cache** — `config.js` fetches with `?t=${Date.now()}` + `cache: 'no-store'`, but if you edit files while the server is running, always hard-refresh (`Ctrl+Shift+R`)
2. **Excel column "Local/Remote" has a newline in the header** — pandas reads it as `'Local/\nRemote'`; openpyxl reads it fine
3. **The original `dashboard.html`** still exists and loads the same JSON, but it renders a full table (all rows visible at once). It's kept for reference. The `search-dashboard.html` is the active page.
4. **Docker setup** uses port 8081 and Nginx. The batch file uses port 8080 and Python. Don't run both simultaneously.
5. **`config.js` is shared** between both dashboards. If you add new fields to the JSON, you must also add them to the `processStreams()` mapping in `config.js` or they won't appear in `getStreams()`.
